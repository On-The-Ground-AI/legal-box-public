3. The client demo, in five minutes

  1. Wi-Fi off first. Then run Chat, Contract Review, Summarize, Chronology — everything works offline.
  2. Settings → Confidentiality. Paste any text; show the masked version — "this is exactly what the AI sees." Shield status and egress lock are shown live.
  3. Terminal proof: lsof -i -P | grep -iE 'legalbox|ollama' — loopback only.
  4. Audit Log: metadata-only entries, PII counts, local_only on every line.
  5. Point technically-minded participants at the public /technical page for the full write-up.

Full script with talking points and FAQ answers: docs/CONFIDENTIALITY_DEMO.md.

5. Pending decision — make the GitHub repo public

Not yet done, and deliberately not done automatically. The homepage and technical page now describe an "open-core" model — MIT-licensed self-hosting, plus a paid managed option — and the license file already says MIT. But On-The-Ground-AI/legal-box is currently a private repository (verified: github.com/On-The-Ground-AI/legal-box returns 404 to the public). The site copy is written to stay honest about this — it says "request access by email," not "clone it from GitHub" — but the narrative only becomes fully true once you flip the repo to public.

Before flipping it, worth a deliberate pass over:

  • Git history for anything sensitive — client names, API keys, internal notes in commit messages (a secrets scan is worth running)
  • Whether any planning docs (this dashboard's source included) should move to a private location first
  • Whether you want a CONTRIBUTING.md / issue templates in place before public issues start arriving
  • Confirming the LICENSE and NOTICE.md attributions are exactly how you want them presented publicly

When ready: repo Settings → Danger Zone → Change visibility → Public on GitHub, then swap the placeholder clone URL on /technical#self-host and the homepage's "Request source access" copy for a direct link.
